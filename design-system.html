Candler Park Fall Fest map, Oct 3–4 2026. This page is generated from src/styles/tokens.css and src/styles/components.css — the same files the app loads. If a swatch here is wrong, the token is wrong.

2 · Iconography

Phosphor, regular weight, drawn white on a category-coloured disc. One glyph per category, used identically on the map, in chips, and in panel badges.

Do: reuse the category glyph everywhere that category appears.
Don't: introduce a second glyph for the same category, or tint a glyph anything but white — the two paper-only ops discs (a navy bolt on the generator's yellow, a charcoal trash can on the dumpster's white) are the documented exceptions, in PIN_INK.

Panel

One component, two variants, chosen by viewport. The bottom sheet (below 1024px: full width on a phone, 560 max centred on a tablet) and the docked panel (1024px and up: floating beside the map, persistent, the directory is its resting state). In the code and the tests .sheet is the hook for the bottom variant; the component is the Panel.

Rule · closeClose is always top-right, on the first row under the handle. In every sheet state, so it never moves when the content does. (Apple's HIG puts the dismiss control in a sheet's top-trailing corner and navigation in the top-leading corner, on the same row.) It is not part of either layer, so it does not animate when you push or pop.
Rule · backThe back label names the previous screen, short. The area's shortName ("‹ In the Park", "‹ Candler Park Dr"), the way an iOS back button names where you came from, never the list's full title: its "· Art Market" would be said again on the row below. Same on the docked panel's back row. A run that needs a different short name gets it as a field on its record in src/data/areas.js, not by trimming the title in a component.
Rule · no repeatNothing on a card repeats its header. A booth reached from its list (the back row showing) drops the area and "Art Market" from its subtitle and keeps only what the back row does not say: "no booth number", "★ Featured artist". If nothing is left, there is no subtitle line, not an empty one. A booth opened straight from the map has no back row, so its subtitle names the area. The same test applies to every card's body: a line that only restates the title or the subtitle is cut.
Anatomy.ffc-panel__handle (a --tap-min band holding a 4px __handle-bar; a button with an accessible name) → .ffc-panel__header (the stage holding the back row and/or the __titleline: __badge, __title, then __sub; plus __close) → .ffc-panel__body (the only thing that scrolls) → .ffc-panel__footer. The docked variant adds __masthead (the resting header) and a __back row.
NavigationOne sheet, a stack one level deep: push from the right, pop to the right, height held. Tapping a booth in an area's list pushes: the booth slides in from the right while the list shifts a little left underneath it. ‹ back pops: the booth slides out to the right and the list returns at its previous scroll position. The sheet's height does not change (data-stack holds it at the list's height; the booth's content scrolls if it must) and the header eases between its two lengths. ItemPager steps pan sideways and never add a back step. The way you step in is the way you step out. Reduced motion: a crossfade, no slide.
DetentsFull (--sheet-max-height) is how a sheet opens. Peek (--sheet-peek-height) is how it opens while a filter chip is on. Drag the handle up, or tap it, for full; tap again for peek. A swipe down closes (from peek) or steps down to peek (from full, with a chip on).
TokensSheet: --sheet-max-height --sheet-peek-height --sheet-detail-min-height (a booth opened from the map never gets shorter, so the footer never moves) --shadow-push. Map safe area (measured at runtime): --map-inset-top --map-inset-bottom. On .ffc-panel, each pointing at a semantic token: --panel-bg --panel-fg --panel-title --panel-muted --panel-rule --panel-radius --panel-shadow --panel-pad --panel-motion --panel-accent --panel-push-shift.
Safe areaEvery pan or zoom that targets a pin or a booth (a pin tap, a booth square, a list row, an ItemPager step) centres it in the visible map between the two insets: the bottom edge of the header + chip row, and the top of the sheet at its current height (0 when closed). The pan limits run past the festival by the same amounts so any pin can reach it.

5 · Accessibility floor

Contrast4.5:1 for text. --text-muted is 5.4:1 on white; the greys it replaces (#9aa0ac, #8b90a0, #8a8f7f) all failed.
TapControls: --tap-min 44px, no exceptions. Pins: a --pin-hit 44px circle centred on the marker, even where the visual is 28 or 40. 44 CSS px is 44pt on iPhone (Apple HIG).
Target spacingWCAG 2.2 AA (2.5.8, Target Size Minimum) asks for 24px, with an exception where undersized targets have enough spacing around them. We hold the stricter bar: 44px, and no tap target overlaps another at any zoom stop, on either map or on paper. That no-overlap rule is how pins satisfy 2.5.8 in a dense park: when two hit areas would cross, the lower-priority pin waits for a closer stop (from: 'detail' in pins.js) or the two are moved edge to edge. Booth squares are the one exception to 44: at the Detail stop each is its own 9.4-unit cell, and the ItemPager is how you page through a run when a finger can't pick one.
Type12px floor. No 11px.
SelectionNever opacity alone — a navy fill, or a navy ring where the fill carries category.
Focus2px navy ring, 2px offset, on every interactive element.
Closed UIHidden, not just translated off-screen, so it leaves the tab order.

6 · Interaction states

How the map behaves, as built after the 10/6 interaction PR. Cells tagged OPEN are still undefined or inconsistent; round 1's six were decided by Ernest on 10/6 and are built. The same content is in docs/interaction-states.md.

States

S1Map only — No chip, no sheet.
S2Chip on — A filter chip is on, no sheet. The chip's pins are bright and on top; everything else is dimmed and takes no taps.
S3Sheet open · full — No chip. A pin card, a stage lineup (the schedule), the Food Court, or an art-market area's booth list, at full height.
S4Chip on + sheet · peek — A sheet opened while a chip is on opens at peek height (--sheet-peek-height) so the map stays visible. The ItemPager is not shown.
S5Chip on + sheet · full — The same sheet after the handle was tapped or dragged up.
S6List → booth (inside the sheet) — A booth opened from a row in an area's list: ONE sheet, the content slid to the booth, a back row (‹ <area>) above the title, the ItemPager in the footer. The chip is off (an area list clears it).
S7Booth opened from the map — A booth opened by tapping its square: the same booth sheet with no list behind it, so no back row.

The zoom stop is a second dimension: any state can be at any of the three stops. The docked panel (desktop) has no peek, no handle and no ×; the directory is its resting state and ‹ All locations (or ‹ <area>) goes back.

The three zoom stops

1 · OverviewArea blobs, no individual booths. Pins flagged overview (stages, Food Court, Kidlandia, first aid, bike valet, beer, merch, the art-market markers) plus any chip's pins. The whole festival is in frame.
2 · BoothsBlobs give way to the individual squares (no numbers). Amenity pins appear, except those held back with from: 'detail'. Art-market markers still show.
3 · DetailBooth numbers and area names are drawn; the art-market markers have faded out so every booth is its own target; from: 'detail' pins appear; the Food Court pin gives way to its stalls.

State diagram

Layers clear from the top: the sheet first, then the chip. S5 closes like S4. S6 and S7 close with ×, swipe down, back or a tap on empty map (to S1); S7 also opens from a booth square in S1. The browser back button follows the same layers: sheet first, then chip. Not drawn: reset (to S1 from anywhere) and a pin tap while a sheet is open (swaps the card). The Mermaid source is in docs/interaction-states.md.

The agreed rules

  1. Chip on → its pins stay bright and everything else dims. Dimmed pins and every booth square take no taps.
  2. Closing the sheet keeps the chip on. × , swipe down and Esc close the sheet only.
  3. A tap on empty map clears one layer at a time: first the sheet, then the chip. So does the back button.
  4. Tapping the chip again turns it off. The map stays where it is.
  5. Close is always top-right, on the first row under the handle. In every sheet state; it never moves when the content does.
  6. The way you step in is the way you step out. A booth opened from a list pushes in from the right and ‹ back pops it to the right; the sheet's height is held; paging with the ItemPager never adds a step.
  7. A control you tap repeatedly never moves. The ItemPager is pinned to the bottom of the sheet, above the home bar.
  8. No tap target overlaps another, at any zoom stop, on either map, or on paper. Pins have a 44px hit area (--pin-hit), controls are at least --tap-min.
  9. Times are always readable on one line. A set time is a fixed-width column that never wraps; the artist wraps instead.
  10. A pan or a pinch is never a tap. Only a genuine tap clears a layer.
  11. Every pan that targets a pin or a booth centres it in the map safe area, and runs again after a pinch settles and after a resize.
  12. Swipe down from a full chip sheet stops at peek; the second swipe closes. On a phone on its side the sheet is capped at peek.

7 · Governance

How the system changes. The system is the files plus design-system/manifest.json; the manifest is what an agent asks (npm run ds -- component ItemPager, or the ff-design-system MCP server in .mcp.json).

Propose → review → adopt

ProposeA pull request that changes a token, a component, a name or a rule. It carries, together: the CSS, design-system/manifest.json (run npm run manifest; hand-write only cssClass, file, inStates, rules, doNot and the rules themselves), the Names table in §3 if a name is added, renamed or removed, this page, docs/interaction-states.md if a state changed, a line in design-system/CHANGELOG.md and the version bump. A value that is not a token becomes one, here, before it is used.
ReviewCI: manifest is current (the committed manifest is what a fresh generation produces), npm run test:ds, lint and the e2e suite. New CSS goes through npm run ds -- check. Open questions and skipped items go in docs/pr-notes.md.
AdoptErnest approves and merges. Nothing is part of the system until it is merged, and no agent merges its own proposal.

Versioning

MajorSomething code may depend on is removed or renamed, or the meaning changes: a token, component, CSS class or rule removed; a token or class renamed; a token moved between tiers; a rule tightened so that code which passed now fails. Also the end of a deprecation (below).
MinorSomething is added, or visibly changes, and nothing breaks: a new token, component, part, variant or rule; a token's value changed; a deprecation announced.
PatchWords only: a note, a description, a doNot, a rule's reason, an enforcedBy or source pointer, a typo.
Whereversion and updated in the manifest, and the newest heading of design-system/CHANGELOG.md; npm run test:ds fails if the two disagree. Starts at 1.0.0.

Deprecation

MarkA component: "deprecated": true, "replacement": "<Name>" on its manifest entry. A token: start the comment above it in tokens.css with Deprecated: use --other; the manifest picks it up. Same idea as hidden: true on a pin. This is a minor version.
One versionIt stays, still working, for that one version. npm run ds -- check warns on every use and names the replacement.
RemoveIn the next major, the entry, the CSS and the Names row go together, and the CHANGELOG says what replaced it.
